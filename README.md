# 🎬 Semantic Movie Genre Tagger

A multi-label movie genre classification system that predicts multiple genres from a movie's plot summary using dense semantic embeddings and a tuned neural network.

The project explores the transition from traditional sparse text representations to transformer-based semantic representations, comparing linear and non-linear classifiers before deploying the final model through Streamlit.

## 📌 Project Overview

Movie plots often contain contextual information that cannot be captured reliably through isolated keyword matches. This project uses Natural Language Processing (NLP) and machine learning to identify the semantic content of a plot summary and predict the genres that best describe the movie.

Unlike a conventional multi-class classifier, this is a **multi-label classification** problem: a movie can belong to several genres simultaneously.

The final pipeline uses:

1. The `all-MiniLM-L6-v2` Sentence Transformer to convert a plot summary into a 384-dimensional dense embedding.
2. A tuned Multi-Layer Perceptron (MLP) to predict probabilities for 175 genre labels.
3. A probability threshold of `0.25` during the notebook's optimized evaluation.
4. A Streamlit interface that displays the three highest-probability genres for a user-provided plot.

## 🎯 Objectives

- Build an end-to-end multi-label text classification pipeline.
- Compare TF-IDF features with transformer-generated semantic embeddings.
- Evaluate linear and non-linear classifiers on different text representations.
- Investigate how representation dimensionality affects classifier performance.
- Optimize the decision threshold for micro-averaged F1.
- Tune the neural network architecture and regularization settings.
- Serialize the trained model and label encoder for local inference.
- Deploy an interactive prediction interface using Streamlit.

## 📂 Dataset

**Dataset:** CMU Movie Summary Corpus.

The project combines two files:

- `plot_summaries.txt` — movie identifiers and plot summaries.
- `movie.metadata.tsv` — movie metadata, including movie titles and genre information.

The two datasets are merged using `movie_id`, retaining records that have both a plot summary and metadata.

### Data preparation

1. Load the plot summaries and movie metadata.
2. Merge the files using the common `movie_id`.
3. Parse the stringified JSON genre dictionaries and extract the genre names.
4. Count the occurrences of each genre.
5. Retain genres appearing at least 50 times.
6. Remove movies that have no remaining labels after filtering.
7. Convert the genre lists into a binary target matrix using `MultiLabelBinarizer`.

| Dataset characteristic | Value |
|---|---:|
| Movies after preprocessing | 41,761 |
| Unique genre labels retained | 175 |
| Minimum genre frequency | 50 |
| Training samples (80%) | 33,408 |
| Testing samples (20%) | 8,353 |
| Train-test split random state | 42 |

The five most frequent genres used for selected class-level reports were Drama, Comedy, Romance Film, Thriller, and Action.

## 🧠 Machine Learning Workflow

### 1. Multi-label target encoding

Each movie is associated with a list of genres. `MultiLabelBinarizer` converts these lists into a binary matrix with one column per genre.

For example:

| Movie | Action | Comedy | Drama | Thriller |
|---|---:|---:|---:|---:|
| Movie A | 1 | 0 | 1 | 0 |
| Movie B | 0 | 1 | 0 | 1 |

A value of `1` indicates that the movie belongs to the corresponding genre. Multiple columns can be active for the same movie.

### 2. TF-IDF + Logistic Regression baseline

The first representation used `TfidfVectorizer` with English stop-word removal and a maximum vocabulary size of 10,000 features. The classifier was Logistic Regression wrapped in `OneVsRestClassifier`, allowing an independent binary classification problem to be trained for each genre.

A preliminary Grid Search tested TF-IDF vocabulary sizes of 5,000, 10,000, and 20,000 on a 5,000-row subset using three-fold cross-validation. The best subset-search setting was 5,000 features, with a cross-validation micro F1 of 0.1535. The subsequent full training pipeline used 10,000 maximum features and unigrams plus bigrams.

The baseline's best global threshold in the notebook was `0.60`, producing a micro F1 score of **0.4230**.

### 3. MiniLM embeddings + Logistic Regression

The next experiment replaced sparse TF-IDF vectors with dense embeddings generated by the Hugging Face Sentence Transformer:

- Model: `all-MiniLM-L6-v2`
- Embedding size: 384 dimensions
- Classifier: `OneVsRestClassifier(LogisticRegression(...))`

The default binary predictions produced a micro F1 of 0.2204. Scanning probability thresholds found `0.75` to be the best threshold in this experiment, with a micro F1 of **0.2581**.

This experiment demonstrated that changing the feature representation does not automatically improve performance when the classifier is not suited to the structure of the new representation.

### 4. MiniLM embeddings + MLP

The final modeling direction retained the 384-dimensional MiniLM embeddings and replaced the linear classifier with a Multi-Layer Perceptron.

The initial MLP used:

| Parameter | Value |
|---|---|
| Hidden layers | `(256, 128)` |
| Activation | ReLU |
| Solver / optimizer | Adam |
| Maximum iterations | 500 |
| Early stopping | Enabled |
| Random state | 42 |

The model was trained directly on the multi-label binary target matrix. Its initial threshold-optimized micro F1 was **0.4616** at a threshold of `0.25`.

### 5. Hyperparameter tuning

`RandomizedSearchCV` was used to explore a small set of MLP configurations.

| Hyperparameter | Values explored |
|---|---|
| Hidden layer sizes | `(256, 128)`, `(512, 256)`, `(128, 64, 32)` |
| L2 regularization (`alpha`) | `0.0001`, `0.001`, `0.01` |
| Initial learning rate | `0.001`, `0.005` |

Search configuration:

- `n_iter=5`
- `cv=2`
- `scoring='f1_micro'`
- `random_state=42`
- `n_jobs=-1`

The selected configuration was:

```python
{
    "hidden_layer_sizes": (256, 128),
    "alpha": 0.0001,
    "learning_rate_init": 0.005
}
```

The tuned model's best threshold was `0.25`, producing a micro F1 score of **0.4580**.

The tuned model's result is close to, but slightly below, the initial MLP's threshold-optimized score of 0.4616. The tuning experiment therefore documents the selected configuration; it should not be interpreted as a measured improvement over the initial MLP.

## 📊 Model Comparison

The table below reports the threshold-optimized micro F1 scores recorded in the project log and notebook.

| Model | Text representation | Best threshold | Micro F1 |
|---|---|---:|---:|
| TF-IDF + Logistic Regression | Sparse, up to 10,000 features | 0.60 | 0.4230 |
| MiniLM + Logistic Regression | Dense, 384 dimensions | 0.75 | 0.2581 |
| MiniLM + Initial MLP | Dense, 384 dimensions | 0.25 | 0.4616 |
| MiniLM + Tuned MLP | Dense, 384 dimensions | 0.25 | 0.4580 |

### Tuned MLP: selected genre results

At the tuned model's threshold of `0.25`, the notebook reported the following class-level results:

| Genre | Precision | Recall | F1-score |
|---|---:|---:|---:|
| Drama | 0.54 | 0.96 | 0.69 |
| Comedy | 0.48 | 0.67 | 0.56 |
| Romance Film | 0.39 | 0.67 | 0.49 |
| Thriller | 0.42 | 0.67 | 0.52 |
| Action | 0.47 | 0.62 | 0.54 |

The lower threshold increased recall for these genres, particularly Drama. This comes with a precision trade-off: more actual genre labels are recovered, but more false-positive labels may also be produced.

**Evaluation note:** The notebook scans thresholds using probabilities from the test split. Consequently, the reported best-threshold test scores are threshold-selected on that same test split and should be treated as experimental results rather than an unbiased final estimate. For a stricter final evaluation, select the threshold using a validation set or out-of-fold training predictions, then evaluate once on an untouched test set.

## ⚙️ Application & Deployment

The trained MLP and the genre label encoder are exported using `joblib`:

- `movie_genre_mlp_tuned.pkl`
- `genre_label_encoder.pkl`

The local application is built with Streamlit. The application loads the saved classifier and label encoder, uses `all-MiniLM-L6-v2` to encode a user-entered plot summary, and obtains genre probabilities from the classifier.

The UI uses `numpy.argsort` to select and display the **top three highest-probability genres**. This is a presentation strategy and is distinct from applying the notebook's global `0.25` threshold to return every genre above that threshold.

The transformer is cached with Streamlit's `@st.cache_resource` so its weights do not need to be loaded again on every rerun.

## 🚀 Running the Project Locally

### 1. Clone the repository

```bash
git clone https://github.com/pranavppramod/Semantic-Movie-Genre-Tagger.git
cd Semantic-Movie-Genre-Tagger
```

### 2. Create and activate a virtual environment (recommended)

**Windows:**

```bash
python -m venv venv
venv\Scripts\activate
```

**macOS / Linux:**

```bash
python -m venv venv
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Launch the Streamlit application

```bash
streamlit run app.py
```

Streamlit will provide a local URL in the terminal.

### Model artifacts

The application requires the trained model and label encoder in the paths expected by `app.py`. If these files are not included in the repository, place the exported `.pkl` files in the appropriate `models/` directory before launching the app.

The Sentence Transformer may download its pretrained weights the first time it is loaded. An internet connection is therefore required for the initial model download unless the weights are already cached locally.

## ⚠️ Limitations & Future Improvements

- The project uses plot summaries as its only predictive input; metadata such as cast, director, release year and keywords are not incorporated into the classifier.
- A single global threshold may not be optimal for every genre. Per-label thresholds could be investigated using validation data.
- The threshold scan uses the test split in the current notebook. A dedicated validation strategy would provide a more reliable final estimate.
- The top-three application display always returns three labels, even when all predicted probabilities are low. A confidence-aware fallback or threshold-based option could improve this behavior.
- Rare genres are excluded by the minimum-frequency filter, so the model cannot predict those discarded labels.
- More systematic tuning, class-specific analysis and additional transformer models could be explored.
